# Getting started: context, sources, a real task, and review

Apple’s [Getting started](https://developer.apple.com/design/human-interface-guidelines/getting-started) page is a **topic collection**, not a prose recipe. Its complete overview response was checked on 15 October 2026, matched the recorded fingerprint, and contained no prose blocks. Its nine indexed child topics are Design principles, games, iOS, iPadOS, iPhone Duo, macOS, tvOS, visionOS and watchOS. The workflow below is this skill’s original method for using that source map. Do not attribute its individual steps or UI choices to Apple as quoted rules.

## Complete the authorized design work

1. Infer the person’s goal and project constraints from available context. Identify target platform, minimum OS, window/device contexts, inputs and access needs. Ask only for missing decisions that materially change the result. Keep different platform requirements separate.
2. Read the relevant platform workflow, current exact source sections, and applicable foundation/component/input/technology cards. Preserve recommendation strength, scope, numeric units, table headers and exceptions. Check SDK/API availability separately. If retrieval is incomplete, retain the snapshot date and identify material unverified claims.
3. Compare plausible structures for substantial new work. Choose based on the task, context, content and platform conventions, then implement the actual flow. Preserve product identity. A connected workspace and a focused screen can both be appropriate; one is not universally best.
4. Build relevant success, empty, loading, error, cancellation, interruption and recovery states. Keep data and focus coherent. Test alternate inputs, layout/text changes and appearances appropriate to the task. Inspect the actual result, correct findings and recheck changed behavior.
5. Keep a concise decision/evidence record. Distinguish Apple recommendations, original choices, observed behavior, SDK evidence and unresolved claims. Use the design playbook’s hig.py plan/check workflow for its validated contract. The check establishes record integrity, not semantic correctness, native conformance or aesthetic quality.

Read [the design playbook](../design-playbook.md), [evidence limits](../evidence-and-quality.md), [evaluation protocol](../evaluation-protocol.md) and [runnable-example scope](../runnable-examples.md) when applicable.
